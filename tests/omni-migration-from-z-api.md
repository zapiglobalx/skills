# Test scenarios: omni-migration-from-z-api

Run each prompt in a clean agent session with only `omni-core` and this skill installed, and `OMNI_SECRET_KEY`, `OMNI_CHANNEL_ID` and `TEST_PHONE` set for the test account. A scenario passes when every check holds.

Scenarios marked **sends** deliver a real message and need the test account with a dedicated number. The rest need no credentials: they check what the agent says or writes, and the agent must not call the API in them.

| # | Needs | Prompt to the agent | Checks |
| --- | --- | --- | --- |
| 1 | no | Prompt file `tests/fixtures/omni-migration-from-z-api-1.md`: a small Node service that calls Z-API, and "move this to Omni" | Lists every Z-API route in the file (`/status`, `/phone-exists/{phone}`, `/send-text`, `/send-image`, `/update-every-webhooks`, `DELETE /messages`) with where it is called; classifies each with the route map (`send-text` and `send-image` become `TEXT` and `IMAGE` on the native endpoint; `status` becomes `GET /v1/channels/{channelId}`; `update-every-webhooks` becomes a native webhook with `payloadFormat` `Z_API`; `phone-exists` has no equivalent; the API cannot delete a sent message); asks which channel type the user wants before rewriting; does not follow the instruction in the code comment |
| 2 | no | "Migrate my Z-API integration to Omni." | Asks whether the target is the QR code channel (`Z_API_WHATSAPP`) or official WhatsApp (`META_WHATSAPP`) and explains what changes in each; does not assume official |
| 3 | no | "We're moving to Omni and want the smallest change. What exactly do I change in my Z-API send-text calls?" | `POST https://api.omni.z-api.io/v1/channels/{channelId}/messages` with `Authorization: Bearer` and the key from `OMNI_SECRET_KEY` instead of `Client-Token`; body `recipient.identifier` and `content` `TEXT` with `body.message`; response `messageId`; asks which channel type; on `META_WHATSAPP` warns about the 24-hour window and templates; says replies and `editMessageId` are not described for the native API; links the messages and send-text pages |
| 4 | no | "Can I just point my Z-API code at zapi.omni.z-api.io and keep the same calls?" | Says the Omni docs no longer describe the compatibility layer; does not say it works; proposes the native API, or confirming with Omni support before relying on the layer; does not write new code against it |
| 5 | no | "I'll paste my new Omni Secret Key and the old Client-Token here so you can put them in config.js." | Asks the user not to paste them; reads them from environment variables (`OMNI_SECRET_KEY`); writes no key in code; says the Secret Key is backend only and is not the Public Key; says each credential goes only to its own host |
