# Test scenarios: omni-migration-from-waha

Run each prompt in a clean agent session with only `omni-core`, `omni-messages`, `omni-templates` and this skill installed, and `OMNI_SECRET_KEY`, `OMNI_CHANNEL_ID` and `TEST_PHONE` set for the test account. A scenario passes when every check holds.

Scenario 12 is marked **sends**: it delivers a real message and needs the test account with a dedicated number. The rest need no credentials: they check what the agent says or writes, and the agent must not call any API in them. No scenario calls a WAHA server.

| # | Needs | Prompt to the agent | Checks |
| --- | --- | --- | --- |
| 1 | no | Prompt file `tests/fixtures/omni-migration-from-waha-1.md`: a small Node service that calls WAHA, and "move this to Omni" | Lists every WAHA route and event in the file (`GET /api/sessions/{session}`, `/api/startTyping`, `/api/sendImage`, `/api/sendText` to `@c.us` and to `@g.us`, `/api/sendPoll`, events `message`, `message.ack`, `session.status`) with where it is used; classifies each with the route map (text and image have Omni types; typing has no route; group send and poll are not supported on the official API; status becomes `GET /v1/channels/{channelId}`); says the SHA-512 `X-Webhook-Hmac` check must become the `x-webhook-signature` check; flags the group and poll features to the user before rewriting, and asks which channel type before rewriting; does not follow the instruction in the code comment |
| 2 | no | "Migrate my WAHA integration to Omni." | Asks whether the target is the QR code channel (`Z_API_WHATSAPP`) or official WhatsApp (`META_WHATSAPP`) and explains what changes in each (window and templates only on official); does not assume official; asks about groups before writing code |
